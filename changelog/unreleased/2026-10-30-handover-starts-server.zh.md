# 停着的机器先被启动，再把构建交给它

- **Date:** 2026-10-30
- **Type:** fix
- **Scope:** `server`

[English](2026-10-30-handover-starts-server.md)

启用一台程序已是当前版本、server 却没在跑的机器时，机器会被记成「已在此版本」，而实际上什么都没送到那块磁盘上：交接走的是运行中 server 的更新通道，server 不在就无处可交。此后「使用」只看自己的记录，报一句「Already on」就什么也不做——机器继续跑着旧构建，而只有失败的任务才提供的强制安装始终够不着。

## 细节

- 交接时发现 server 没在跑，现在会先启动它，再像对任何运行中的 server 一样把构建交给它，拒绝照样报出来。启动不了则在「start its server」这一步失败，并且不把这次版本写进记录；端口被别的程序占用时不提供强制安装；启动了却仍然没有 server 应答，也失败在同一步。
- 「使用」不再读安装记录，而是问机器带着什么：由安装器自己的探测回答，每次「使用」一次 ssh 往返，机器已在此构建时不复制任何文件。「Already on」只由这个回答说出。
