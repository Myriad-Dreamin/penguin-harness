# 每种安装方式都验一遍沙盒

- **Date:** 2026-09-29
- **Type:** process
- **Scope:** `ci`, `release`

[English](2026-09-29-sandbox-channel-matrix.md)

沙盒能不能真正起来，现在按安装渠道在全新安装上逐一实测，不再由单元测试间接推断。

- **`scripts/sandbox-matrix.mjs` 检查一份安装。** 它启用本平台的沙盒后端，读新建 Session 的 `confinementSupported` 与 `noNetworkSupported` 两个标志，再经真实的 Agent 循环跑一条写工作区之外的命令和一条写工作区之内的命令。不需要任何模型凭据：脚本自己提供一个按脚本应答的模型端点。它既可以在全新的主目录上启动安装好的程序，也可以驱动一个已在运行的服务器，结果写成一份带结论与原因的 JSON。
- **新增 Sandbox matrix 工作流，覆盖 Linux 一列。** 在 x64 与 arm64 runner 上分别安装：按发布流程组装的 CLI 安装包；同一份安装包经从标准输入读入的安装器安装（给出发布 tag 时改为该 Release 的一行安装器）；以及全局安装的 npm 包——并逐一检查。它在手动触发时运行，矩阵本身有改动时也会运行。
- **Docker 镜像冒烟也检查沙盒。** 原本就会启动容器、登录、等待健康检查的冒烟构建，现在还会跑矩阵里 Docker 的那一格。
- 失败已有记录的格子报为「已知空缺」而不是失败；目前是 npm 全局安装与 Docker 镜像两格，它们还不带沙盒后端。
