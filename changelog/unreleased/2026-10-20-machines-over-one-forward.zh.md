# 机器的流量走它唯一的那条 forward

- **Date:** 2026-10-20
- **Type:** refactor
- **Scope:** `server`, `web`

[English](2026-10-20-machines-over-one-forward.md)

机器上的服务端现在经它 ssh 会话里持有的那条 forward 抵达——本机上一个 loopback 监听，每条连接是会话里的一条通道——不再用机器自己的套接字。请求代理、API 客户端、终端中继与机器聚合事件流都改为用 node:http 与 `ws` 直接拨这个地址，和对待任何本机服务端一样，因此它们之下不再有谁知道 ssh 是什么。机器套接字缓存、它的 API 套接字中继以及其上的事件 hub 一并退役，浏览器可见的 API 套接字事实也随之消失。

## 细节

- 每台机器、每个端口保留一条 forward：首次使用时打开；该机器的会话被替换、它的服务端换了端口、它断开连接，以及本代服务端退出时丢弃。拨不通的结果不记存。
- 聚合流把每台被观察机器的 `/api/events` 当作普通的 text/event-stream 经 forward 读取，把每个 `server_event` 重新包成 `machine_event`，每帧自带 `id`，使一个标签页的流跨多台机器仍可续读。每台机器的读取用该机器自己的最后事件 id 续读，退避从 500 ms 到 10 s；重新连接的标签页收到 `resync_required`，而不是由本服务端再保留一份缓冲来回放。
- `MachineApi` 与热更新推送把 forward 的本机端点与机器上服务端端口分开传入：套接字拨端点，`Host` 头写机器上服务端监听的端口——规范主机名校验要求如此。
- 机器详情对话框不再显示 API 套接字一行：它读的那个事实已不存在。

## 兼容性

- `MachineInfo`（`GET …/machines`）不再提供 `socket` 字段。读过它的客户端将读不到该事实；API 其余部分未变。
